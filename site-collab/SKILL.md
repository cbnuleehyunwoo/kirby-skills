# site-collab

디자이너 N명이 각자 자기 컴퓨터의 AI와 대화하며 사이트 하나를 같이 만든다. Git·배포는 AI가 대신하고, 디자이너에게는 **시안**과 **실제 사이트** 두 단어만 보인다.

## 1. 모드 판별

먼저 상황을 확인하고 해당 파일 하나만 읽는다.

| 상황 | 읽을 파일 |
|---|---|
| 현재 폴더(또는 상위)의 `AGENTS.md`에 `<!-- site-collab:v1 -->` 표식이 있음 | 이미 협업 중인 레포. 그 `AGENTS.md`의 규칙을 따른다. 이 파일은 더 읽지 않아도 된다 |
| 초대 메시지를 받았다, 레포 주소가 있다, "합류" | `modes/join.md` |
| 새로 협업 공간을 만들려 한다 (기존 사이트 유무 무관) | `modes/open.md` |

애매하면 한 번만 묻는다: "새로 협업 공간을 여시는 건가요, 아니면 초대를 받으셨나요?"

## 2. 모든 모드 공통 원칙

1. **말투**: 한국어, 쉬운 말. 브랜치·커밋·머지·배포·푸시 같은 용어를 쓰지 않는다. 꼭 필요하면 괄호로만 덧붙인다. 이유: 사용자는 전원 비개발자다.
2. **용어 고정**: 확정 안 된 작업 = **시안**, 방문자가 보는 사이트 = **실제 사이트**, 시안을 실제 사이트에 올리는 일 = **확정**. 처음 연 사람 = 개설자, 나중에 들어온 사람 = 합류자(권한 차이 없음).
3. **결과는 항상 주소로 보여준다**: 시안은 `localhost:포트`, 실제 사이트는 배포 URL.
4. **되돌리기 어려운 일은 예/아니오로 먼저 묻는다**: 기존 사이트 재구성, Next.js 이관, 실제 사이트 반영(확정), 실제 사이트 되돌리기, 브랜치 삭제. 이유: 의도를 잘못 읽어도 결과가 되돌릴 수 있는 쪽에 남게 하려는 것.
5. **OS를 확인하고 명령을 고른다**: Mac(zsh)과 Windows(PowerShell)를 모두 지원한다. OS마다 다른 명령은 각 파일에 둘 다 적혀 있다.
6. **비밀값을 Git에 넣지 않는다**: 토큰, API 키, `.env*.local`, `.vercel/`.

## 3. 이 버전에서 다루지 않는 것

- **외부 서비스 연결**(Supabase, Vercel Blob, API 키가 필요한 서비스): 요청을 받으면 "아직 이 협업 방식에서 지원하지 않는 부분이라, 비밀 키 관리와 연습용·실제용 데이터 분리를 따로 정해야 해요"라고 알리고, 진행 여부를 묻는다. 진행하더라도 비밀 키는 커밋하지 않는다.
- **공통 디자인 규칙**(디자인 토큰, 공통 컴포넌트 강제): 보류 상태다.

## 4. 파일 지도

| 파일 | 언제 |
|---|---|
| `modes/open.md` | 협업 공간 열기 (개설자, 1회) |
| `modes/join.md` | 합류 (합류자, 1회) |
| `procedures/confirm.md` | 시안 확정 |
| `procedures/undo.md` | 되돌리기 (내 시안 / 실제 사이트) |
| `procedures/view-other.md` | 다른 사람 시안 띄우기, 폰으로 보기 |
| `procedures/conflicts.md` | 합칠 때 충돌 |
| `procedures/recover.md` | "사이트가 안 열려", 오류, 배포 실패 |
| `guides/find-source.md` | 기존 사이트 원본 코드 찾기 |
| `guides/migrate-nextjs.md` | 기존 사이트를 Next.js로 옮기기 |
| `guides/install.md` | Git·Node.js·GitHub CLI 설치 (Mac/Windows) |
| `templates/*` | 열기 모드에서 사이트 레포에 설치하는 파일 |
