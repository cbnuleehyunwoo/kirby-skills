# 되돌리기

먼저 무엇을 되돌리려는지 구분한다.

| 사용자 말 | 대상 | 확인 |
|---|---|---|
| "아까 게 나았어", "원래대로", "방금 거 취소" | 아직 확정 안 된 **내 시안**의 최근 수정 | 없음. 하고 나서 알린다 |
| "올린 거 취소해줘", "어제 확정한 거 되돌려줘", "실제 사이트 원래대로" | **실제 사이트**에 이미 올라간 확정 | 필수 |

애매하면 묻는다: "아직 안 올린 시안을 되돌릴까요, 실제 사이트에 올라간 걸 되돌릴까요?"

## 내 시안 되돌리기

내 브랜치에서 내가 한 커밋만 본다. main을 merge한 커밋은 제외한다.
```
git log --oneline --no-merges origin/main..HEAD
```
- "한 단계 전": 가장 최근 커밋 1개를 되돌린다.
  ```
  git revert --no-edit <sha>
  git push
  ```
- "더 전으로": 사용자에게 최근 수정 목록을 화면 말로 보여주고("1. 제목 크게 2. 버튼 색 파랗게 …") 어디까지 돌릴지 고르게 한 뒤, 최신 것부터 차례로 `git revert --no-edit`.
- 끝나면: "한 단계 전으로 돌려놨어요 → localhost:3000. 더 전으로 갈까요?"

`git reset`으로 기록을 지우지 않는다. 이유: 이미 푸시돼 다른 사람의 겹침 확인에 쓰이고 있고, 되돌린 것을 다시 되살릴 수도 있어야 한다.

## 실제 사이트 되돌리기

1. 대상 찾기: `git log --oneline -15 origin/main`. 확정 1회 = 커밋 1개다.
2. 확인 질문. 다른 사람의 확정이면 그 사실을 함께 말한다.
   > <이름>님이 <언제> 확정한 "<요약>"을 실제 사이트에서 되돌릴까요? <이름>님 작업이라 미리 알려드리는 게 좋아요.
3. 동의하면, 되돌림 전용 브랜치에서 처리하고 확정 절차로 올린다.
   ```
   git fetch
   git switch -c <핸들>/revert-<slug> origin/main
   git revert --no-edit <sha>
   git push -u origin HEAD
   ```
   그다음 `confirm.md`를 3단계(빌드 확인)부터 실행한다. 확정 동의는 2에서 이미 받았다.
4. 되돌릴 커밋 이후에 같은 파일을 바꾼 확정이 있어 `revert`가 충돌하면, 무엇이 겹치는지 화면 말로 설명하고 `conflicts.md` 기준으로 진행한다.
